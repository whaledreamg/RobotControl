安全包络几何 getEnvelopeDefinition / getEnvelopeSnapshot / setEnvelopeGeometry（SI：米、弧度）

      

        胶囊一律以 baseAtZero 口径给出：全关节零位时、在该机器人基坐标系中的两个端点 + 半径，外加绑定关节序 jointIndex∈[0,dof]（随前 jointIndex 个关节运动，0=固定于基座，dof=随法兰）。与「运动学几何」的轴线口径同源，可用同一套规则摆放。
        
两层半径：configuredRadius 是所配几何轮廓，effectiveRadius = 配置半径 + 生效膨胀量，才是实际拦停的边界。三维视图勾选「叠加包络胶囊」即可叠在模型上目视核对（青=配置，琥珀=有效；红=自上次清障以来命中过，清障即撤除标红）。
        
编辑权由机型档案显式声明：常规机械臂为研发内置只读，变位机等现场装配机构才可写。写入为整臂替换，硬校验不过整体拒绝；通过则落 data/robot/{id}-runtime.yaml，须重启生效（胶囊增删会改变装配期展开的检查对表）。
        
连接性是硬校验：每根胶囊都要直接或经由别的胶囊连到某个关节原点上（按配置半径判相交），有悬空胶囊即整份拒绝并点名序号与实际间隙——胶囊由机型三维模型量取，一根摆错位就意味着那一段的保护范围整条错位。响应中的 warnings 只剩零位恒定相交提示（不拒绝，可写进 selfExemptPairs 消掉）。胶囊不必盖住骨架：骨架只是运动学连线，与实物轮廓无必然关系。
        
要为某款机型从头确定胶囊，用顶部「胶囊编辑器」页签：不连控制器也能填 MDH 摆位、三维拖拽、自检、出 Envelope: 段 YAML。
        
总开关关闭时定义与快照同样可查（校核本就发生在开启保护之前）；status.state 逐台说明这台臂是否真的在判定（active / disabled / bypassed / noLinkPose / noCapsules / selfOnly）。

安全监控分级响应 getSafetyResponseMap → 编辑 → setSafetyResponseMap（即时热刷新 + 落盘 {id}-runtime.yaml）

      

        每类监控触发时执行所选响应级：immediateDisable 立即失能闭锁 · servoQuickStop 伺服 CW=2 超时保底（型号须支持，否则回退立即失能）· pathStopThenDisable 轨迹减速再失能 · pathStop 轨迹减速不闭锁（可直接恢复）· zeroSpeedHold 零速保护（型号须支持 CSV）。
        
每类监控只接受与其物理语义相符的允许集合（末列，由内核 allowedResponses 给出，下拉只列合法项）：提交集合外的组合会被整体拒绝；配置文件中的历史越界值在启动时钳制为缺省并置常驻告警（13406）。
        
axisFault（伺服故障/断连）恒为立即失能不可改；axisEmergencyStop 为派生项（可写可回读，但实际响应由下方「急停延迟」联动决定），二者在此置灰不提交。
        elbowOverspeed（肘部过速）仅全局 manual 且机型有肘点时启用，缺省 pathStop；阈值见「运行参数」中的 manualElbowMaxLinearVelocity。
        
jointTrackingError 的缺省已由 servoQuickStop 改为 pathStopThenDisable（仅影响未显式配置的部署）；jointPositionLimit 缺省维持 servoQuickStop——选 pathStopThenDisable 时停距绑定 stopDecelTimeMs，实测可越限 5°~9°，须自行核算裕度。
        
envelopeCollision 的缺省亦已改为 pathStopThenDisable（仅影响未显式配置的部署）：包络命中判的是「再走下去会撞上」而非已经撞上，停距本就由膨胀量预留；前提是膨胀量须盖得住 stopDecelTimeMs 导出的减速停距，盖不住就改配 servoQuickStop 以最短距离停住。
        安全事件一律使原运动挂起（非丢弃），清障回锚点后可 resumeMotion 续放。

寄存器从站

        
把寄存器开放给上位读写 (Modbus TCP / PROFINET / EtherNet/IP)

        
业务插件 RegisterSlaveBusiness（组件 registerSlave）。三种形态同时只能起一种，method 是落盘的期望形态、runningMethod 是本次开机实际在跑的，改形态须重启控制器才生效。
只有软从站需要映射窗口：Modbus 主站按寄存器地址直接点名，中间没有窗口这层。窗口的方向由寄存器可写性推导——可写归输入（上位写进来）、只读归输出（机器人发出去）；偏移由控制器按选中顺序累加，单方向上限 1440 字节。
映射失效即拒绝启用：已映射的寄存器被删除/改名/改类型时从站起不来，须重新选择映射并在上位重做组态；保存成功 ≠ 从站起来了，改完记得查状态。
